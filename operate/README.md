# SSR 服务端渲染
在nodejs环境无法对dom和bom进行操作，需要借助第三方库帮助jsdom
<br/>
*Npm  i  jsdom*
<br/>
jsdom模拟浏览器环境，使开发者在nodejs环境中使用DOM API对页面内容进行修改。<br/>
这种直接在服务端操作页面内容并将最终内容（js文件）返回给浏览器的方式被称为<b>SSR 服务端渲染</b>
<br/>
如：nuxtjs渲染
*拓展： 尝试提取文件中的页面内容，并通过jsdom操作元素内容。*

# SSR 和 CSR 的区别
1.页面加载方式：
    <li>csr: 服务器返回一个初始的html文件，浏览器下载完js文件后通过编译执行文件内容动态生成更新的页面内容。缺点：初始内容加载时，内容较少，页面结构和样式可能存在一定的延时（即首屏加载缓慢）。</li>
    <li>ssr: 服务器预先生成完整的html页面内容返回给浏览器，浏览器接收下载渲染好的html文件。优点：页面初始加载速度较快。</li>
2. 内容生成与渲染：
    <li>csr: 由客户端的javascript脚本对页面的内容进行生更新渲染。当数据发生变化时，js会重新生成并更新dom。优点：开发方式更灵活，可以创建复杂的交互和动画效果。</li>
    <li>ssr: 由服务器在页面渲染时编译执行应用程序的代码，生成最终的html文件。优点：对于静态或动态交互较少的内容可以提供较好的首次加载性能。</li>
3. 用户交互和体验：
    <li>csr: 客户端渲染使用ajax或者websocket连接服务器进行数据交互，然后通过js更新页面的内容。优点：提供较快的页面切换和响应速度。缺点：对于搜索引擎🔍和seo（搜索引擎优化）需要额外的处理。</li>
    <li>ssr: 由服务器生成页面的初始内容，通过在服务器执行用户的操作内容，然后服务器返回页面更新后的内容。优点：首屏加载性能较好，对搜索引擎友好。</li>

# SEO 搜索引擎优化
爬虫在通过搜索引擎抓取内容时只能获取到html文件内容，无法获取js文件内部的内容
seo主要对T（title）D（description）K（keywords）三个方面内容进行操作，以及页面语义化内容（如：header、nav、footer）
